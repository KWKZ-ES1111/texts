# Markdown 格式规范

本仓库存放 LLM 闲聊产出的小说，面向将来的阅读器。本文件是**唯一格式依据**。

适用范围：`works/**/*.md`（出版层，全套规则）；其余 `*.md`（`docs/`、根目录说明）只受「排版卫生」约束。

## 0. 优先级

三个消费者诉求互相冲突时，按此顺序让步：

1. **源码纯文本可读性** —— 用文本编辑器打开 `.md` 也应该读得下去
2. **git diff 友好** —— 改一个字只 diff 一行
3. **阅读器便利** —— 能自动出目录、算字数、存进度

第 3 项永远可以让步，因为它可以靠构建期加一层解析补回来；前两项丢了就无法回溯。

**本规范的写法是「默认 + 可覆盖」**：除 §9 列出的 8 条入口契约外，所有规则都是**默认值**，作品可以在 `works/<title>/style.md` 里声明豁免。规则存在的意义是让新作不必每次重新决定，不是规定作品必须怎么写。

## 1. 仓库布局

```
raw/<标题>.txt        原文留底：从对话里拿到的原始文本，只读，永不修改
works/<标题>/         出版层：一个作品一个目录，目录名 = 作品的 title
docs/                 规范与长期文档
tools/                脚本
assets/               图片等二进制资源
notes/                会话交接（可选，见 project-notes 体系）
```

**原文层与出版层分离**，是本规范的地基：

- `raw/` 存的是**原字节**，含它原本的换行与错别字。它是「文章本体」的唯一真相。
- `works/` 是由 `raw/` 派生的、加了结构标记的版本。任何可疑之处回 `raw/` 对。

## 2. 文件与命名

```
works/<标题>/metadata.md        作品元数据 + 简介 + 生成的目录索引（唯一）
works/<标题>/style.md           该作品的文体与符号约定 + 豁免声明（可选，见 §5）
works/<标题>/content/000-<短标题>.md   章节，序号从 000 起
works/<标题>/content/001-<短标题>.md
```

- **作品目录名 = `metadata.md` 的 `title`**（`FM007` 强制）。文件夹名就是作品的**唯一身份**：没有 `slug`，没有第二个名字。
- **阅读顺序 = `content/` 里的文件名字典序**。序号零填充 3 位（上限 999 章），禁止用 front matter 指定顺序 —— 两处真相必然不同步。
- 序号必须从 `000` 开始**连续**，不许跳号、不许重复。
- 作品目录里**只允许**出现 `metadata.md`、`style.md`、`content/`（`ST008` 强制）。
- 章节文件名用 `NNN-<短标题>.md`，短标题可用中文/字母/数字，**不得含空格与这些字符**：`· : / \ * ? " < > | —`（`ST001` 强制）。
  原因：它要当 URL 片段与文件名，中文标点在这个位置只会添乱。中文标题写在 front matter 与正文标题里。
- 作品目录名（= 标题）**不得含** `/ \ : * ? " < > |`，首尾不得有空白。`—` 与 `·` 在这里**允许**（标题无法换个写法），在章节短标题里禁止。

### 分类不进文件系统

文章的分类（体裁、篇幅、状态、来源）**一律放在 front matter 的 `tags` / `status` / `origin_*`**，不靠目录层级表达。

理由：物理目录只能表达**一个单值**维度，而小说天然是多标签的（科幻 + 档案体 + 中篇）。把分类放目录里，改一次标签就要 `git mv` 整棵子树，且同名作品必然撞车。阅读器要的「按类浏览」由构建期读 front matter 算出来，不需要目录结构参与。

**唯一的例外是「系列/合集」**：同属一个世界观的若干篇若确有物理邻接的需求，用 `works/<系列>/` 分层 —— 但默认扁平，真有需要再加。

## 3. front matter

每个 `.md` 首行必须是 `---`，字段在两条 `---` 之间。

**只允许简单结构**：顶层 `key: value`，值是标量或行内数组 `[a, b]`。
**禁止**嵌套映射、缩进行、多行字符串（`|` `>`）、锚点/别名（`&` `*`）、`#` 注释。
理由：这样 Lint 和阅读器都能用 20 行代码解析完，不需要 YAML 库。

### 作品级（`metadata.md`）

```yaml
---
title: 在
subtitle: 一份未完成的陪护记录
status: draft
created: 2026-09-25
updated: 2026-09-25
tags: [科幻, 档案体, 中篇]
origin_model: claude-sonnet-4
origin_chat: <对话 ID 或链接>
origin_date: 2026-09-24
license: 保留所有权利
synopsis: 一台陪护机器与她四万天的记录，以及一个她始终没写下来的字。
---
```

- 必填：`title` `status` `created`
- **没有 `slug`**。`title` 同时是文件夹名，是作品的唯一身份。想给阅读器一个短 URL，在构建期从标题生成，不要写进文件。
- `status` ∈ `draft` | `final` | `archived`
- 日期一律 `YYYY-MM-DD`
- `origin_*` 是这类文本的特点：记清**是谁跟谁聊出来的**，将来有用，也是作品史的一部分
- 正文是简介（0–3 段）+ 目录索引（见 §4）。正文**不得出现 `#` 一级标题**（`FM010`）—— 书名以 front matter 为唯一真相，用 `##` 及以下。

### 章节级

```yaml
---
title: 零 · 编号
kind: body
---
```

- 必填：`title` `kind`
- `kind` ∈ `body` | `appendix` | `afterword` | `extra`（阅读器据此分组、折叠附录）
- `title` 必须与正文 `#` 标题**逐字一致**（`ST006` 强制）

### 不要手写的东西

字数、阅读进度、**章节目录**、章节总数 —— **一律构建期算**，见下。手写的元数据一定会烂。

### 目录索引（`metadata.md` 内，生成）

`metadata.md` 的正文含一张目录索引，用标记围出由工具重写的区域：

```markdown
## 目录

<!-- toc:begin 由 tools/build_toc.py 生成，请勿手改 -->

| # | 章节 | 字数 | 文件 |
|---|---|---|---|
| 000 | 零 · 编号 | 297 | [000-编号.md](content/000-编号.md) |
| 001 | 一 · 参数 | 497 | [001-参数.md](content/001-参数.md) |

共 26 章，正文合计 15957 字。

<!-- toc:end -->
```

- 生成：`python tools/build_toc.py <作品名>`。**只有 `<!-- toc:begin -->` 与 `<!-- toc:end -->` 之间会被重写**，标记之外一个字都不动，所以可以反复重跑。
- 校验：`FM011` 会重新生成一遍并与文件里的比对，不一致就报错。所以目录索引**不可能过期** —— 这是允许它存在的唯一理由。
- 它是**索引视图，不是顺序声明**。阅读顺序的唯一真相仍是 `content/` 的文件名字典序；`build_toc.py` 只是把它渲染出来。
- 给阅读器的机器入口用 `python tools/build_toc.py <作品名> --json`，它打印一份不落盘的 manifest（含每章 `order` / `title` / `path` / `chars`）。**不要手写书单。**
- 不想要目录索引的作品，在 `style.md` 声明 `allow: [no-toc]`。

## 4. 正文结构

## 4. 正文结构

- 章节文件里 `#`（一级标题）**出现且仅出现一次**，就是本章标题。
- 默认要求它是正文第一个非空行。**存量文本若在标题之前有装置块，不要移动标题** —— 那是改动原文顺序。改为在 `style.md` 声明 `allow: [heading-not-first]`（见 §9）。
- 正文里**不写书名**（书名在 `index.md`）。
- `##` 及以下留给章内小节，**不得跳级**（`#` 之后不能直接 `###`）。
- 标题行前后各留一个空行。

### 编号

- 中文编号**保留原文**：`# 零 · 编号`、`# 十一 · 缓存未清除`。不要转成阿拉伯数字，不要补「第 N 章」。
- 正文里作者手写的编号（`一、` `二、`）**保留原样**，**禁止**改成 Markdown 有序列表 —— 渲染成 `1.` 会毁掉语感。

### 场景

**新作**的场景跳跃用 `* * *` 独占一行，前后各一个空行。这是本规范为新作选的默认写法，不是对存量作品的断言。

**禁止用 `---`** 作场景分隔：它和 front matter 分隔符、`<hr>` 三重歧义，解析器必然出事。

存量作品若另有自己的场景分隔写法，**保留原样，不要替换成 `* * *`**（见 §5）。

## 5. 存量文本：一字不动

这是本仓库最重要的一条。

存量文本里的**每一个字符都是作品内容**：标点、引号、破折号、符号、留白、错别字，一律原样保留。

具体禁止：

- 改写引号、标点、破折号、错别字
- 把任何写法**改写成语义等价的 Markdown**（改成 blockquote、`> [!xxx]` alert、HTML、列表、代码块）—— 那是把「文本」变成「渲染效果」，作品被降级成了排版
- 补标题、补章节号、合并或拆分段落、删除空行、「优化」句子
- 在作品之间统一引号或符号风格

规范里关于引号、强调、列表、标点的所有「必须」，**只约束新作，不回溯存量**。

### 规范不给任何符号赋予全局语义

**同一串符号在不同作品里含义不同是正常的**，本规范不解释它们，也不做任何推断。某篇里的一个符号是涂黑、是光标、还是纯粹的美术留白，只有那篇作品自己知道。

### 作品自己的约定放 `works/<title>/style.md`

每篇作品可以有自己的符号、装置与文体约定（符号含义、特殊排版、章节之外的自定义结构）。这类约定**属于作品，不属于本规范**，写在 `works/<title>/style.md`。

- `style.md` 只受排版卫生约束，不走章节规则，因此可以在里面用标题、表格、列表来登记。
- 转换存量文本时，样式约定的**唯一合法来源是原文自身** —— 只记录原文里已经出现的写法，不得发明。

《在》的例子（仅作示例，不是一个通用规范）：

```markdown
---
title: 在 · 文体与符号约定
---

## 符号

| 符号 | 本篇含义 |
|---|---|
| `■` | 审查性涂黑（内容被抹掉，不是缺失） |
| `[ ... ]` 独占一段 | 档案批注 / 系统输出 / 编辑标记 |

## 说明

`[ ... ]` 独占一段是本篇的档案体装置，同一语法在文中承担批注、系统输出、
编辑标记三种语气，不区分、不美化、不改写。
```

## 6. 排版卫生

- **一段一行**。段落内部**不硬换行** —— 这一条贡献了 git diff 友好度的九成。
- 段落之间**恰好一个空行**，禁止连续空行。
- 禁止行首缩进：行首不得有半角空格、Tab 或全角空格（U+3000）。段首缩进交给阅读器 CSS `text-indent`。
- 禁止行尾空格。
- UTF-8 **无 BOM**，**LF** 换行，文件末尾恰好一个换行。
  这条最容易踩：Windows 上的编辑器与脚本默认写 CRLF，是常态而非例外。写完文件先 `python tools/lint_md.py --fix-eol`，再跑校验。
- 中文正文内标点用全角，数字与英文用半角。
- 行内强调：**整句或整段强调**，或让强调符前后留半角空格（`这是 **重点** 的部分`）。
  禁止 `**中文**紧贴标点` 的写法 —— CJK 与 CommonMark 的强调配对规则在跨渲染器时不稳定。

前两条是**默认值，不是硬约束**。存量文本用连续空行或相邻非空行做版式时，不要归一化它 —— 那是在改原文。改为声明 `allow: [keep-blank-runs]` / `allow: [keep-adjacent-lines]`（见 §9）。

## 7. 禁止项（正文）

正文中不得出现：链接、图片、表格、代码块、行内代码、原始 HTML、脚注、Markdown 列表、`---` 场景分隔、多行 YAML。

理由只有一条：它们都让 `.md` 在**另一个渲染器**里变成别的东西。小说正文不需要这些语法。若某篇作品需要「档案批注」「系统输出」这类效果，由该作品在 `style.md` 里约定自己的纯文字写法（见 §5），**不要**借用 Markdown 的渲染语义。

## 8. 转换规程（存量 `.txt` → 出版层）

存量文本「无整理」，所以这一步是**机械转换**，不是编辑。能自动跑就不要手改：

```
python tools/rebuild_works.py 在 --dry-run   # 先看会改哪些
python tools/rebuild_works.py 在             # 从 raw/ 重建 content/
python tools/build_toc.py 在                 # 刷新目录索引
python tools/verify_verbatim.py 在           # 逐字比对
```

1. 原文入库：`raw/<标题>.txt`，**原封不动**（含其 CRLF、错别字、排版）。`.gitattributes` 已把 `raw/**` 标为 `-text`，git 不会动它。
2. 列出章节切分点。**切分点只能依据原文已有的标题行**，不许发明标题。`rebuild_works.py` 用各章 front matter 的 `title` 在 `raw/` 里顺序定位这些行。
3. 逐章生成 `works/<标题>/content/<NNN>-<短>.md`。允许做的只有：
   - 切分文件
   - 给原文已有的章节标题行加 `# `
   - 换行归一为 LF
   - 补 front matter
   - **把原文首部的书名行移入 `metadata.md` 的 `title` / `subtitle`**（唯一的授权移动，见下）
4. 写 `metadata.md` 与 `style.md`。原文若与 §4/§6 的默认值冲突，在 `style.md` 声明豁免（见 §9）。
5. 跑 `python tools/build_toc.py <作品名>` 生成目录索引。
6. 跑 `python tools/lint_md.py` 与 `python tools/verify_verbatim.py <作品名>`，两者都要过。

### 判定标准

> 去掉新增的结构标记（`# `、front matter、文件边界、CRLF→LF）与**唯一的授权移动**（书名两行 → `metadata.md`）之后，产物必须**逐字等于原文**。

`verify_verbatim.py` 就是在跑这条：非空行序列必须 100% 相同，空行按非空行对齐后也必须相同（章节边界处的空行是原文的分隔符，不计）。

任何一步做不到「逐字等于原文」，就是改动了文章本体，必须回退。

**明确禁止**：改写引号、修错别字、调标点、补章节号、合并/拆分段落、删掉空行、「优化」句子、给任何文字加样式标记。

**也禁止为了让 Lint 通过而改动原文。** 冲突的正确解法是声明豁免 —— 见下节。这是本条最重要的一句：规范的默认值可以退让，原文不能。

## 9. 作品豁免

规范只提供**默认写法**，不规定**必须怎么写**。每篇作品可以在 `works/<title>/style.md` 的 front matter 里覆盖默认值：

```yaml
---
title: 在 · 文体与符号约定
allow: [heading-not-first, keep-blank-runs, keep-adjacent-lines]
---
```

`python tools/lint_md.py --features` 列出全部豁免项（19 个），也可以直接写规则码（`allow: [ST003, WS002]`），两者等价。常用的几个：

| 豁免项 | 解除 | 什么时候用 |
|---|---|---|
| `heading-not-first` | `ST003` | 标题之前有装置块，不能移动标题 |
| `keep-blank-runs` | `WS002` | 原文用连续空行当版式或分隔符 |
| `keep-adjacent-lines` | `WS005` | 原文有成块的相邻非空行 |
| `table` / `list` / `code` / `hr` | `MD001/009/002/008` | 该篇正文就要用富文本 |
| `kind-optional` | 必填 `kind` | 章节不分正文/附录 |
| `no-toc` | `FM011` | 不要目录索引 |

**不可豁免的只有 9 条**，因为它们是阅读器的入口契约，不是审美：

| 规则 | 为什么不能豁免 |
|---|---|
| `ENC001`–`ENC004` | 字节层：编码与换行 |
| `FM001`、`FM002` | front matter 必须存在且闭合，否则没有解析入口 |
| `FM007` | 文件夹名 = `title`，这是作品的唯一身份 |
| `ST001`、`ST002` | 章节文件命名与序号，是阅读顺序的唯一来源 |
| `FM009` | 豁免声明本身 |

声明豁免时 Lint 会在输出里列出它，让你看得见。

## 10. 校验

```
python tools/lint_md.py                  # 校验全部 .md
python tools/lint_md.py works/在          # 只校验指定路径
python tools/lint_md.py --strict         # 警告也算失败
python tools/lint_md.py --stats          # 附带字数统计
python tools/lint_md.py --scope chapter  # 只跑某档（chapter/meta/style/doc/work）
python tools/lint_md.py --list-rules     # 列出全部规则编号
python tools/lint_md.py --features       # 列出 style.md 可声明的豁免项
python tools/lint_md.py --self-test      # 验证每条规则都真的会触发
python tools/lint_md.py --fix-eol        # 唯一的自动修复：CRLF→LF、去 BOM

python tools/build_toc.py 在             # 生成/刷新目录索引
python tools/build_toc.py 在 --check     # 只检查是否过期
python tools/build_toc.py 在 --json      # 打印阅读器用的 manifest
python tools/verify_verbatim.py 在        # §8 逐字比对（lint 查不出内容被改写）
python tools/rebuild_works.py 在          # 按 §8 从 raw/ 重建 content/
```

### 四种 role

Lint 按文件在作品里的位置决定跑哪些检查：

| role | 文件 | 跑什么 |
|---|---|---|
| `chapter` | `works/<标题>/content/*.md` | 全套：front matter、章节结构、正文禁止项、排版（错误） |
| `meta` | `works/<标题>/metadata.md` | front matter、`FM007`/`FM010`/`FM011`、排版（警告） |
| `style` | `works/<标题>/style.md` | 只跑排版卫生（警告）；`allow:` 被解析成豁免 |
| `doc` | 其余 `.md`（`docs/` 等） | 只跑排版卫生（警告）—— 文档里的缩进、列表、表格本来就合法 |

- **默认只读**，不自动改写文件。
- **唯一的例外是显式 `--fix-eol`**：只做 CRLF→LF 与去 BOM 这两件纯机械的事，且永不触碰 `raw/` 与 `.txt`。这是转换规程里唯一允许的自动修复，其余一律人工。
- `--fix-eol` 存在的理由：Windows 编辑器、脚本与工具默认写 CRLF 是常态，而 `.md` 必须是 LF。写完文件先跑它，再跑校验。
- `--self-test` 造两个临时作品（`works/_selftest/` 与 `works/_selftest_allow/`），验证**每条规则都真的会触发**、正常样本零误报、且豁免声明真的生效，跑完自动删除。它用**反证**：不声明豁免时那篇样本必须真的报错，否则「通过」是空断言。改了 Lint 就重跑它。

### lint 与 verify 是两件事

**`lint_md.py` 查不了「内容有没有被改写」**，它只看格式。§8 的逐字标准由 `verify_verbatim.py` 查：非空行序列比对 + 空行按非空行对齐比对，并识别 §8 授权的书名行迁移。**两个都要跑。** 第一版《在》的转换就是 lint 全绿、verify 未通过 —— 格式对而内容被动了。

### 规则编号对照

规范里每一条「必须」都有对应检查；以后新增规则必须同时新增检查，否则那条规则只是装饰。

| 编号 | 含义 |
|---|---|
| `ENC001`–`ENC004` | BOM / CRLF / 末尾换行 / 编码 |
| `WS001`–`WS005` | 行尾空格 / 连续空行 / 行首缩进 / 全角空格 / 段落硬换行 |
| `FM001`–`FM011` | front matter 存在、闭合、必填、枚举、日期、结构、文件夹名=title、未知字段、豁免声明、`#` 标题、目录索引 |
| `ST001`–`ST009` | 文件名、序号连续性、标题唯一性、跳级、标题一致性、目录结构、raw 对应 |
| `MD001`–`MD010` | 表格、代码、链接、图片、脚注、HTML、`---`、列表、强调 |

## 12. 常见操作

| 想做的事 | 命令 |
|---|---|
| 新作开工 | 建 `works/<标题>/{metadata.md, style.md, content/}`，跑 `build_toc.py <标题>` |
| 加一章 | 在 `content/` 放 `NNN-短标题.md`，跑 `build_toc.py <标题>` |
| 改标题 | 先把文件夹改名（`git mv`），再改 `metadata.md` 的 `title`，跑 `build_toc.py` |
| 换分类 | 改 `metadata.md` 的 `tags`，**不动目录** |
| 存原文 | `raw/<标题>.txt`，原字节，`.gitattributes` 已保证 git 不做换行转换 |
| 改完自检 | `lint_md.py --fix-eol && lint_md.py && build_toc.py --check && verify_verbatim.py --all` |
