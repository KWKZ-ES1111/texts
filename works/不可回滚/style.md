本文件登记《不可回滚》的文体约定与空白层约定。规范见 `docs/md-spec.md` §5、§9。

## 豁免声明

本篇声明 0 项豁免。`style.md` 的 front matter 里没有 `allow:`，正文完全落在规范的默认值内。

它是新作，但同样走 §8 那一套：原文存放在 `raw/不可回滚.txt`，出版层由它派生，逐字比对已通过。`ST009` 的警告因此消失了。

## 原文与派生

    20|这一篇的原文**不是**从对话里直接倒出来的 `.txt`，是先把章节写出来的；`raw/不可回滚.txt` 由这 28 章逆推而成。

推法只有两条动作，正好是 §8 允许的那两条的逆运算：去掉 front matter、把章节标题行前面的 `# ` 去掉。空行一个字没动。

已验证这是个**不动点**：

```
python tools/rebuild_works.py 不可回滚 --dry-run   # 28 章全部「不变」
python tools/verify_verbatim.py 不可回滚            # 非空行 867 行，相似度 100.0000%
python tools/verify_verbatim.py 不可回滚 --strict-blank   # 空行 866 行，也无差异
```

也就是说，从 `raw/` 重建出版层会得到一模一样的文件。改章节内容必须**同时改 `raw/`**，否则 verify 会报出来 —— 这条约束是故意保留的。

## 以 raw 为准时的换行

`raw/在.txt` 保留的是原文自带的 CRLF（1187 行全 CRLF）。本篇的原文是 LF 写成的，所以 `raw/不可回滚.txt` 是 1733 行全 LF、无 BOM、末尾一个换行。

两篇不一样是对的：`raw/` 存的是**各自原文的原字节**，不是一种统一格式。`.gitattributes` 的 `raw/** -text` 保证 git 不对它做换行转换，这个差异会一直保留。

## 文体

- 第一人称，叙述者是陈屿（记忆系统工程师），全篇用现在式语感回望，不做档案体。
- 对话用中文弯引号“ ”。叙述内部引述的短语、句子、条目用直角引号「 」，与对话区分。本篇不使用 `■`、`[ ]`、`【 】` 这类装置符号，也不使用列表与表格。
- 章内若有场景跳跃，用 `* * *` 独占一行，前后各一个空行。实际正文一处都没有用到。
- 涉及系统输出的地方，一律写成叙述句或单行引文，不制造多行文本块。
- 正文里出现的「一、二、三」是陈屿手写的单子，属于作者手写编号，不是 Markdown 列表。
